Tern window plugin · Oh My Pi sessions

Your OMP sessions in Tern. On SidePulse.

Keep running Oh My Pi inside Tern. tern-sidepulse watches the OMP panes in your open Tern windows, local and remote, and sends one status to SidePulse — working, waiting for input, completed, failed, or idle — so the LEDs and the menu bar tell you when a session needs you. The plugin never reads a transcript, submits a prompt, approves an action, or changes a window layout.

What you see

One status, the most actionable one.

The OMP sessions visible in your open Tern windows combine into one session on SidePulse, including sessions on attached remote hosts. The strips show SidePulse's default LED programs; your configured animations apply.

  • Cyan Roll
    working

    Any session working (your configured working animation)

  • Amber Pulse
    waiting_for_input

    Any session waiting for input (an ask, an approval) outranks working

  • Solid Green
    completed

    A turn finished for 15 s, unless the session resumes first

  • Amber Pulse
    blocked_error

    A turn failed for 30 s, unless the session resumes first

  • Idle Pulse
    idle_ready

    Nothing visible, or all idle (clears this plugin's status)

Closing a pane, losing a host connection, disabling the plugin, or closing the last window clears the status within about 20 s. Multiple Tern windows combine into one session on SidePulse: duplicates across windows are reduced, never counted.

How it works

From window state to one status.

Each window sends a complete snapshot. One local coordinator combines the windows and delivers the result to both SidePulse receivers.

  1. window.luau each Tern window

    Observes cx.agents:list() every 5 s and on agent events. Keeps OMP panes on connected hosts whose surface role is omp.session; sends a complete snapshot.

  2. bridge.py helper, per call

    python3 -I -S, an argument vector, a 4 s timeout, and bytecode under the plugin data directory.

  3. coordinator one per user

    Singleton lock, 15 s leases, and priority failed › waiting › working › finished › idle. Bounded retry; clears and exits 5 s after the last lease ends (60 s cap if SidePulse is unreachable).

  4. events.sock SidePulse menu-bar app

    Receives the combined status through a private local socket.

  5. relay-events.sock SidePulse headless service

    Receives the same status independently of the menu-bar app.

Private by design

Six agent fields in, one status out.

The plugin never reads working directories, model names, prompts, assistant text, tool arguments, or transcript paths. OMP tab names and pane titles stay in the coordinator's memory and are never logged or sent to SidePulse.

  • Reads six agent fields, never transcripts

    pane, state, kind, program, host, alive from each agent row, plus host keys and each pane's surface.role. OMP tab names and pane titles stay in coordinator memory only (tests/test_privacy.py).

  • Nothing listens on the network

    The helper, coordinator, and SidePulse receivers communicate through private local sockets. Live observations stay in memory only; a restart never replays a stale prompt.

  • Private local files and sockets

    ~/.local/state/tern-sidepulse has mode 0700; ownership is checked and symlinks are refused. Runtime and state files are written with mode 0600.

  • Bounded requests and state

    Window snapshots are budgeted to 192 KiB and coordinator requests are capped at 1 MiB across at most 32 concurrent connections. State is capped at 64 windows and 512 panes per window.

  • Isolated helper execution

    Argument vectors, never a shell; -I -S isolation and a 4 s timeout. Failed calls back off at 500 · 2ⁿ ms, capped at 30 s.

  • Remote hosts need nothing installed

    No SidePulse, no helper, and no service on a remote host. OMP sessions are observed through the open Tern window connected to that host.

One-time setup

Install once, then plain omp.

Install a copy or link a checkout. The next window snapshot picks up existing OMP sessions; nothing needs restarting.

You need

  • TernTern 0.9.12 or later on macOS
  • SidePulseSidePulse's agent monitor on the same Mac: the menu-bar app, the headless service, or both
  • PythonPython 3.10+ at a known absolute path — Homebrew, a versioned interpreter, python.org, or Command Line Tools. Nothing is installed with pip.
  • Remote hostsNothing to install

  1. Install

    Install a copy from the default branch:

    tern plugin install github.com/alphastorm/tern-sidepulse

    Or link a checkout for development (saving any file in the checkout reloads the plugin):

    tern plugin link /absolute/path/to/tern-sidepulse
tern plugin reload tern-sidepulse

    To pin a release, check out its tag and run tern plugin install /path/to/checkout. To update an installed copy, run tern plugin install --force github.com/alphastorm/tern-sidepulse; for a linked checkout, run git pull.

  2. Confirm it works

    Wait about 5 s after installing or linking. Open the Tern command palette and run tern-sidepulse: doctor. Expect a toast starting with ok: (ok: 0 issue(s); socket delivery is not an LED check). A toast starting with warn: names a check that needs attention.

  3. Watch SidePulse

    Check SidePulse's menu-bar app, or ~/.local/state/sidepulse/agent-monitor/latest.json when running headless. While an OMP session works or waits, one session from origin Tern (OMP in Tern) appears.

A narrow job

Use something else when you want more than a status.

This plugin reports one combined status from the OMP sessions in your open Tern windows. It is not a remote client or an always-on remote monitor.

  • Open or answer an OMP session from your phoneOMP Session Gateway
  • Each pane as its own SidePulse sessionNot in this release — one combined session.
  • Status for remote hosts with no Tern window openNot this — remote hosts follow open windows.
  • Tern outside macOSNot supported.
